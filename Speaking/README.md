# Speaking

Records for conference submissions, talks and speaker assets.

```
Speaking/
  SPEAKING_REGISTER.md          Master. Opportunities + content ledger. Read before every submission.
  Bios/                         Six bios, two persons x three lengths. README says which to use where.
  <Event-Year>/
    decisions.md                Calls made, when, and why
    correspondence.md           Organiser email, terms, recording and rights answers
    submission/                 Every version as sent, with timestamps and confirmation
    deck/                       Numbered deck versions with a change log (created on acceptance)
    delivered/                  What was actually presented, questions from the room, recording
```

## The two rules

**1. The file on disk is the record.** Drafting happens in email or chat; the moment a form is
submitted, the actual pasted text goes in `submission/` with a timestamp and a confirmation
screenshot. A reconstruction is not a record.

**2. No abstract goes out without a ledger read.** `SPEAKING_REGISTER.md` section 2 tracks every
incident, framework and line, and where each has been spent. The unit is the audience, not the
medium. AusCERT2027 requires previously unpresented content, which makes this binding rather
than tidy.
