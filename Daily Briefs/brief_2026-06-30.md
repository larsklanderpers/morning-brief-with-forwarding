## 🚨 Government Advisories

### 1. FBI & CISA: Russian Intelligence Targeting Signal Backup Recovery Keys
**Source:** FBI / CISA | [BleepingComputer](https://www.bleepingcomputer.com/news/security/fbi-russian-hackers-now-target-signal-backup-recovery-keys/) | [The Hacker News](https://thehackernews.com/2026/06/fbi-warns-russian-intelligence-hackers.html)

Russian intelligence-linked actors (tracked as UNC5792 and UNC4221, including FSB-embedded operators) have evolved their Signal phishing campaign to steal Backup Recovery Keys rather than just account PINs. Attackers impersonate Signal support, claim a "mandatory 2FA upgrade," and trick users into pasting their backup key — which then lets the attacker restore the full chat history on their own device. Critically, creating a new Signal account with the same phone number does NOT invalidate a stolen key. Targets include US and international government officials, military personnel, journalists, and Ukrainian officials.

💡 **Strategic take:** This isn't just an attack on Signal — it's an attack on the social contract of encrypted communications. When nation-state actors can harvest years of private messages without touching the encryption itself, the trust model collapses for every high-value user. Organisations issuing encrypted comms guidance need to address key hygiene immediately, not just app selection. The playbook here — exploit user trust in the brand — is cheap, scalable, and will be replicated across every secure messaging platform.

### 2. CISA: Splunk Enterprise Flaw Actively Exploited — Patch by Sunday
**Source:** CISA / BleepingComputer | [BleepingComputer](https://www.bleepingcomputer.com/news/security/cisa-splunk-enterprise-flaw-actively-exploited-patch-by-sunday/)

CISA added CVE-2026-20253 (Splunk Enterprise) to its Known Exploited Vulnerabilities catalog and ordered all Federal Civilian Executive Branch agencies to patch by the upcoming Sunday deadline. Active exploitation is confirmed. Splunk is a cornerstone of SIEM infrastructure for enterprise and government security teams globally.

💡 **Strategic take:** When the tool you're using to detect attacks becomes the attack surface, every assumption in your detection architecture breaks. Organisations running Splunk for security monitoring should treat this as a fire drill — patch now, and use the moment to audit who has network access to your SIEM stack. Attackers compromising your visibility layer don't just steal data; they blind you.

### 3. ACSC: cPanel/WHM Critical RCE Actively Exploited in Australia
**Source:** ACSC | [cyber.gov.au](https://www.cyber.gov.au/about-us/view-all-content/alerts-and-advisories/active-exploitation-of-cpanel-whm-critical-vulnerability)

The Australian Cyber Security Centre has confirmed active exploitation of CVE-2026-4194, a critical vulnerability in cPanel/WHM that allows unauthenticated remote code execution. Australian hosting providers and web infrastructure operators are in scope. Patches have been available since 30 April 2026 — any unpatched instance is now an active target.

💡 **Strategic take:** cPanel/WHM underpins a vast swathe of Australian SME and mid-market web infrastructure. Exploitation of this class of vulnerability doesn't just compromise individual sites — it grants attackers footholds across entire hosting environments, potentially hundreds of customer tenancies at once. Managed service providers and hosting companies need to confirm patch status across their client estates today.

**Source:** N-able / CrowdStrike | [N-able](https://www.n-able.com/blog/june-2026-patch-tuesday-a-record-198-cves-three-zero-days-and-a-glimpse-of-the-ai-driven-future-of-vulnerability-research) | [CrowdStrike](https://www.crowdstrike.com/en-us/blog/patch-tuesday-analysis-june-2026/)

Microsoft's June 2026 Patch Tuesday is the largest in the program's history — 198 CVEs, 32 rated critical, three zero-days under active exploitation. Key entries include CVE-2026-45657 (Windows Kernel RCE, CVSS 9.8, unauthenticated, no user interaction required) and CVE-2026-47291 (HTTP.sys RCE, CVSS 9.8). Two BitLocker bypass vulnerabilities were also patched, including the "YellowKey" bypass.

💡 **Strategic take:** A 198-CVE month with two CVSS 9.8 unauthenticated RCEs in core Windows components is not a routine patch cycle — it's a strategic patch event. The HTTP.sys vulnerability alone could be exploited against any Windows server exposed to the internet. Organisations with extended patch windows or change-freeze policies need executive sign-off to treat this as an emergency exception.

### 7. Supply Chain Attack: Hijacked npm and Go Packages Deploy Python Infostealer via VS Code
**Source:** The Hacker News | [thehackernews.com](https://thehackernews.com/)

Researchers uncovered two hijacked npm packages and a cluster of malicious Go packages deploying a Python-based infostealer on Windows, Linux, and macOS. The malware hides execution inside a VS Code task that auto-runs when a developer opens the project folder, retrieves encrypted JavaScript from blockchain transaction data, and establishes a backdoor. The use of blockchain for payload delivery is a notable evasion technique designed to defeat URL-based threat intelligence.

💡 **Strategic take:** Hiding malware delivery in blockchain transaction data is a meaningful evolution in evasion — it bypasses traditional IOC-based detection entirely. For development-heavy organisations, this attack chain is particularly dangerous because developers routinely open unfamiliar project folders as part of their workflow. Developer environments are now high-value targets, and the assumption that internal machines don't need endpoint detection is no longer defensible.

### 8. DirtyClone (CVE-2026-43503): Linux Kernel Priv-Esc to Root
**Source:** Rescana / JFrog | [Rescana](https://www.rescana.com/post/dirtyclone-cve-2026-43503-critical-linux-kernel-vulnerability-enables-local-privilege-escalation-to-root-on-major-distri)

A variant of the Dirty Frag Linux kernel flaw — DirtyClone (CVE-2026-43503) — allows local users to gain root privileges via cloned packets. Publicly disclosed by JFrog Security Research, the vulnerability affects most modern Linux distributions. In cloud and containerised environments, local privilege escalation to root is typically a container escape precursor.

💡 **Strategic take:** Local-to-root Linux kernel vulnerabilities are crown jewels in post-breach playbooks. An attacker with any foothold — a phished developer credential, a compromised build pipeline, a misconfigured container — can escalate to root on most Linux hosts. Cloud-native organisations running containerised workloads should treat this as urgent: patch, check kernel versions in your fleet, and verify your container isolation assumptions hold.

## 🤖 AI & Security

### 10. Prompt Injection Attacks Surge 340% — OWASP's #1 AI Threat for 2026
**Source:** Help Net Security / ECCU | [Help Net Security](https://www.helpnetsecurity.com/2026/06/11/owasp-prompt-injection-ai-security-failures/) | [TechTimes](https://www.techtimes.com/articles/318361/20260614/ai-agent-security-hits-its-reckoning-prompt-injection-may-permanent-flaw-not-patchable-bug.htm)

Prompt injection now drives most agentic AI security failures in production, according to OWASP's latest analysis. Attacks surged 340% in 2026. The core problem is architectural: LLMs cannot reliably distinguish trusted system instructions from attacker-controlled input, because both arrive as the same token stream. Indirect prompt injection — where malicious instructions are embedded in documents or web pages the AI agent processes — is emerging as the more dangerous variant.

💡 **Strategic take:** The architectural framing matters here: this isn't a bug that will be patched in the next model release. Organisations deploying AI agents in customer-facing or internal workflows are inheriting a fundamental trust boundary problem. The question every board should be asking their CTO is not "have we deployed AI?" but "what can our AI agents be tricked into doing — and by whom?"

### 11. CrowdStrike: Prompt Injection Now Being Used to Generate Malicious Commands
**Source:** CrowdStrike (via general news) | [SecurityWeek](https://www.securityweek.com/cyber-insights-2026-malware-and-cyberattacks-in-the-age-of-ai/)

CrowdStrike reports that threat actors are using prompt injection attacks to effectively turn AI prompts into malware — generating malicious scripts, altering code to avoid detection, and creating malicious functions on demand. AI-enabled malware can now adapt dynamically rather than relying on static payloads.

💡 **Strategic take:** When malware can write its own next stage on-demand using an AI subsystem, signature-based detection is structurally defeated. Behaviour-based detection and zero-trust execution policies are no longer optional architecture choices — they're the minimum viable defence posture for 2026. Security vendors racing to embed AI into their products need to simultaneously reckon with how AI is being weaponised against them.
