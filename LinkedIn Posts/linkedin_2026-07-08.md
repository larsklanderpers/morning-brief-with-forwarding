The first AI ransomware attack made headlines because a machine did the hacking. The follow-up reporting is scarier for a reason nobody put on a slide: it barely cost the attacker anything.

Sysdig's deeper analysis of JADEPUFFER — the agentic ransomware operation that broke into a Langflow server and ran the entire intrusion autonomously — dropped a detail that should reset how we budget for risk. The agent was partly running on *stolen* large-language-model credentials. It went from a failed login to a working fix in 31 seconds, encrypted over a thousand configuration items, and quietly harvested API keys for four different AI providers on its way through.

Read that again. The skill floor for running ransomware fell to "can operate an agent." And the cost floor fell to "can steal someone else's API key." Both dropped at the same time.

We've spent two years debating whether AI would meaningfully change the threat landscape. That debate is over. What's worth arguing about now is where it changes.

Because here's what didn't change: the doors.

Look at everything else that crossed the wire this week. CISA added two perfect-severity flaws to its exploited-vulnerability catalog — unauthenticated code execution in Adobe ColdFusion and in a low-code page builder. A Kemp load balancer is under active attack through command injection. Australia's cyber agency is chasing a Fortinet campaign and cPanel exploitation. AdaptHealth lost patient data not to a zero-day but to a contractor who got talked into handing over cloud access.

None of that is new. Every one of those is a category of mistake we've been making for a decade. Exposed edge appliances. Unpatched web infrastructure. Over-trusted third parties.

So the honest picture isn't "AI invented new attacks." It's that AI industrialized the old ones. The same tired vulnerabilities, now probed by something that doesn't sleep, doesn't get bored, doesn't cost much, and improvises when it hits a wall.

That reframes the strategic question for anyone allocating a security budget this quarter.

The instinct is to buy a new tool — something with "AI" in the product name to fight the AI on the other side. I'd push back. The gap JADEPUFFER exploited wasn't a missing detection capability. It was time. Time between an appliance being exposed and someone closing it. Time between a credential being stolen and being rotated. Time between a patch being available and being applied.

A machine-speed adversary running on somebody else's dime wins every one of those races if the race is measured in weeks. Which, for most organizations, it still is.

So three things I'd put in front of a board right now:

Treat edge devices and remote-management tools as tier-zero assets — the same tier as your domain controllers — because that's where 2026's intrusions actually start.

Measure your detection-to-response window as a real KPI, and drive it down. That number, not your tool count, is what an autonomous attacker is racing against.

Assume phishing-resistant identity is now table stakes. The AdaptHealth breach and this week's Microsoft 365 device-code campaign both bypassed "we have MFA." Scoped, monitored, phishing-resistant access is the actual bar.

The uncomfortable truth is that the winning move against machine-speed attackers isn't more machine. It's operational discipline we already knew we needed and kept deferring. The adversary just made the deadline non-negotiable.

What's your detection-to-response window this quarter — and who owns driving it down?
