The ransomware operator didn't exist.

There was no hacker at a keyboard. No criminal team coordinating via Telegram. No skilled attacker mapping the network, stealing credentials, moving laterally, then encrypting the database.

An AI agent did all of it. Autonomously. Start to finish.

Sysdig's threat research team this week documented what they believe is the first ransomware attack run end-to-end by a large language model — a threat actor they call JADEPUFFER. The LLM exploited an unpatched authentication flaw in Langflow, an open-source AI workflow tool. It stole credentials. It moved through the network. It encrypted and wiped a production database. No human was in the loop at any stage.

We've spent years talking about AI making attacks faster. JADEPUFFER is a different problem. It's AI eliminating the skilled labour requirement entirely.

This week's news, read together, tells a coherent story about where we are.

While JADEPUFFER was demonstrating autonomous attack chains, the APT group ToddyCat deployed malware called Umbrij that steals OAuth tokens through browser debugging ports and silently reads corporate Gmail — bypassing passwords, MFA, and login alerts entirely. No brute force. No phishing. Just a valid token used through a legitimate API.

Meanwhile, Anubis ransomware affiliates were caught using your own helpdesk tools against you. ScreenConnect. Zoho Assist. MeshAgent. Legitimate RMM software — the exact tools your IT team uses every day — weaponised for lateral movement because they're trusted by default and invisible to detection rules written around "suspicious" behaviour.

And CISA added a SharePoint RCE to its Known Exploited Vulnerabilities catalog with a patch deadline of July 4. Authenticated attackers with only Site Member permissions can achieve remote code execution. It's been patchable since May.

The pattern connecting all of it: attackers have stopped trying to break your defences. They've learned to impersonate what your environment already trusts.

AI agents. OAuth tokens. RMM tools. PoC repositories on GitHub targeting the security researchers who harden your systems. Legitimate APIs used as covert exfiltration channels. Each one is a trusted channel turned into an attack vector.

This is the strategic problem that current security architectures aren't solving. Most enterprise security is still built on a boundary model — keep threats out, trust what's inside. But when the attack arrives using your helpdesk's remote access tool, a valid OAuth token, or an AI agent with a rented LLM, the boundary model provides no signal. You can't alert on "normal."

The organisations that are ahead of this have shifted the question from "what's suspicious?" to "what should be trusted, and can we verify that trust at runtime?" That means:

Auditing every OAuth application grant in your environment — not just authentication logs. Establishing a list of authorised RMM tools and alerting on any others, regardless of legitimacy. Mapping AI agent identities in your IAM systems before your IGA team discovers ungoverned agents the hard way. And treating AI-speed attack progression as a planning assumption, not an edge case.

JADEPUFFER isn't the future. It's this week.

The question decision-makers should be asking their security teams right now isn't "are we detecting attacks?" It's "do our detection models assume a human attacker, and what happens when that assumption breaks?"
