# LinkedIn Post — 9 September 2026
**Status:** Draft (review before posting)

973 vulnerabilities. One month. One vendor.

Microsoft's September 2026 Patch Tuesday is the largest security release in the company's history. 973 CVEs. 113 rated Critical. Two already being exploited in attacks. And a proof-of-concept for a Windows Defender zero-day dropped publicly on the same afternoon the patches shipped.

That last detail deserves a second read. A researcher released working exploit code for a Defender privilege-escalation bypass — ShieldCrash — on Patch Tuesday itself. The same day your security team is triaging nearly a thousand vulnerabilities, attackers have a new tool that gives them SYSTEM-level file access on fully patched Windows systems. Timing like that is not coincidence. It is strategy.

And Microsoft is not the only problem today.

N-able N-central, an RMM platform used by managed service providers to manage thousands of client endpoints, has a CVSS 10.0 unauthenticated remote code execution flaw being actively exploited in the wild. CISA added it to the Known Exploited Vulnerabilities catalog yesterday. Australian organisations are already being hit — the ACSC is tracking active exploitation domestically. The patch deadline for US federal agencies is September 11. Three days.

Compromise an RMM server and you do not compromise one organisation. You compromise every organisation that server manages.

Then there is Adobe Commerce — Magento — where a CVSS 10.0 zero-day called StyleSmuggler has been running since September 4. Five days before Adobe disclosed it. Attackers have been deploying a Rust-based backdoor, disguised as an NTP server process, across vulnerable e-commerce stores. If your online store runs Magento, you should assume the five-day window means you may already be compromised, not that you are not.

The pattern across all of this is the same pattern we have been watching compress for three years: **the time between a vulnerability existing and it being exploited is now measured in days or hours, not months**. But most organisational patch cycles are still measured in weeks. Some in quarters.

That gap is where breaches live.

The cybersecurity industry has a habit of treating each of these stories as a separate incident — a Microsoft problem, an Adobe problem, an N-able problem. But they are the same problem: the attack surface is expanding faster than defence operations can track it manually, and the organisations still relying on spreadsheets, monthly patch windows, and "we'll get to it" prioritisation are operating in a threat environment that no longer accommodates that pace.

What should decision-makers do with this?

Stop asking "are we patched?" and start asking "how quickly can we patch when something is being exploited today?" That is the capability gap that matters. The answer to 973 CVEs is not a bigger spreadsheet. It is a programme that can triage, prioritise, and deploy against active exploitation within hours — not a programme that waits for the next maintenance window.

The window has closed.
