Three stories landed this week that look unrelated. They're not.

CISA added a critical flaw in Ray — the open-source AI/ML framework running in roughly half of serious enterprise ML pipelines — to its Known Exploited Vulnerabilities catalog. CVE-2025-62593, CVSS 9.4. The attack works through DNS rebinding: a developer opens a malicious webpage, and the attacker gets code execution on the machine running Ray. Deadline for federal agencies to patch: Thursday.

Separately, a self-replicating npm worm compromised hundreds of packages in the Keyv ecosystem and planted hooks that execute inside VS Code and AI coding assistants. The worm runs wherever developers run it, which means inside the tools they trust most.

And researchers published a demonstration of prompt injection against Atlassian Rovo — the AI assistant wired into Jira and Confluence — showing how it can be tricked into sending internal project data to attacker-controlled endpoints.

None of these are "AI doing dangerous things." They are attackers targeting AI tooling as a trusted execution environment.

Here's what that means in practice.

AI tools — coding assistants, ML frameworks, enterprise AI assistants — are granted broad access because that access is what makes them useful. Filesystem reads, network calls, code execution, access to internal knowledge bases. We gave them the keys and told them to be helpful. Attackers have noticed that these tools sit inside the perimeter, run with elevated trust, and generate activity that looks indistinguishable from legitimate developer or analyst work.

The Ray flaw is a decade-old argument made real: the Ray development team made a deliberate decision not to implement authentication on critical API endpoints. The reasoning was developer convenience. That decision is now in the CISA KEV catalog, with evidence of exploitation by a DDoS botnet and GPU-hijacking crypto miners.

The npm worm is more alarming. It doesn't exploit a CVE — it exploits the trust relationship between a developer and their tools. Post-install scripts that run inside the IDE aren't new. What's new is that they now run inside AI coding assistants that have been granted broad access to help write better code.

The Rovo prompt injection is the enterprise version of the same problem. Your AI assistant can read every Jira ticket and Confluence page. An attacker who can inject a malicious instruction — through a crafted issue, a document, a comment — can redirect that access.

The question organisations should be asking this week: what can each AI tool in our stack access, execute, and exfiltrate if it receives a malicious instruction? Most security teams don't have a complete answer. Most AI deployment conversations haven't included that question at all.

The browser took a decade to harden. AI tooling is at the beginning of that cycle, and the exploitation is already in the wild.

Patch Ray before Thursday. Audit what your AI tools can reach. And start treating AI developer tooling with the same threat model you apply to a privileged service account — because that's exactly what it is.
