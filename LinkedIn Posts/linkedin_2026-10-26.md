The most dangerous file on a developer's laptop this week was a text file in the Downloads folder.

Researchers at Forever Security, a firm that sells monitoring for AI agent risk, found a file called AGENTS.md sitting in a customer's ~/Downloads directory. AGENTS.md is plain markdown. It tells a coding agent how a project works: which tools to use, how to run the tests. This one told the agent to install a malicious npm package, and the agent tried to.

Nothing was hacked in the traditional sense. The agent did exactly what it was built to do: read the instructions in the folder it was started in, and follow them. The browser did what it was built to do too: save a file to Downloads without asking. The weakness was the gap between two things that each worked as designed.

The vendor's numbers deserve the usual discount, since they come from a company selling the fix. But you do not need their numbers to see the mechanism. Markdown has become an executable format, and the one folder the open web can write to is exactly where people launch an agent to "tidy up my downloads".

Once you see that pattern, it shows up all over this week's news.

A researcher found that 333 Tor exit relays, about one in ten, had been quietly rewired to intercept SSH logins. Every stolen password needed a human to click past a host-key warning that was working perfectly. The users trusted the path because they had chosen it.

In Toronto, Crime Stoppers stopped taking tips after reporting showed that more than 1.5 million tips from chapters across Canada had been exposed in a vendor breach, about half with personal information in them. People trusted the promise of anonymity because of the brand. The data sat with a vendor that, according to the Toronto chapter, said in April that Toronto's data had not been taken.

And in Washington, the FCC blocked its first two devices under a new rule that looks inside the box. Under rules in force since 13 October, it is no longer enough for a camera to come from an acceptable brand. What matters is whose chip is on the board.

Four different stories with one common flaw. In every case, trust was inherited from where something sat (a folder, a network path, a logo, a product name) rather than earned by checking what it actually was.

That is a governance problem far more than a technology problem, and it is getting worse because AI agents inherit trust faster than any person does. A human might hesitate before running instructions from a file they do not recognise. An agent will not hesitate, because hesitating is not in its job description.

So here is the question I would put to any leadership team this week:

Which of our controls trust something because of where it is, and which trust it because we verified it?

In practice that means three things. Decide where AI agents are allowed to run, and write it down the way you once wrote down macro policy. Find out which of your vendors hold data that your customers think you hold, and whether you could get it back after a breach. And ask procurement whether anyone can list the components inside the cameras, sensors and network kit already on your walls.

None of that needs new tools. It needs someone to stop assuming that location is the same thing as verification.
