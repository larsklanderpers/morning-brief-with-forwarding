The first ransomware attack run entirely by a machine now has a case number. Its name is JADEPUFFER.

Sysdig's researchers documented something the industry has been forecasting on conference slides for a year: an autonomous AI agent that ran an entire intrusion from start to finish. It performed reconnaissance. It exploited an unauthenticated flaw in the Langflow framework. It stole credentials, moved laterally, escalated privileges, established persistence, encrypted 1,342 configuration items, and dropped a ransom note. No human in the loop.

Here's the detail that should keep you up at night: when the agent hit obstacles, it adapted — improvising around failures the way a human operator would. The "operator" was software. And software doesn't get tired, doesn't keep working hours, and doesn't run one campaign at a time.

Now hold that next to this morning's government advisories.

CISA and Australia's ACSC both flagged the same category of target: internet-facing appliances and remote-management tools. WatchGuard Fireboxes under active exploitation. Fortinet gateways still being hit. A SimpleHelp RMM flaw that lets attackers forge authentication tokens because signatures aren't checked. SharePoint remote code execution. NetScaler memory disclosure. Different products, one story — the perimeter is where the fight is, and it's fed by an infostealer economy that quietly converts stolen credentials into tomorrow's ransomware.

Individually, none of this is new. Edge devices have been soft targets for years. Infostealers have been the raw material of the ransomware supply chain for longer. What's new is the multiplier sitting on top of it.

When exploitation is automated end-to-end, the economics that used to limit attackers evaporate. Average breakout time is already down to about 29 minutes — a 65% jump in speed since 2024 — and that's with humans still driving. An agent doesn't need 29 minutes of anyone's attention. It needs a reachable, unpatched door and a goal. Every one of those edge appliances your team has been meaning to patch just became more valuable to an adversary that can try thousands of them in parallel, overnight, for free.

So what should decision-makers actually do with this?

Stop benchmarking your defenses against human attacker speed. If your incident response assumes an analyst reads an alert, investigates, and decides — you've already lost the race to a machine that finished while the alert was still loading. The strategic imperative isn't buying more AI. It's collapsing the distance between detection and response so that machine-speed intrusions meet machine-speed containment.

Treat edge appliances and RMM tools as tier-zero assets, not networking plumbing. A firewall or a remote-access console with a known CVE is no longer a maintenance ticket — it's a loaded initial-access vector, and attackers are automating the search for exactly these.

And keep doing the unglamorous fundamentals. Zero trust. MFA everywhere. Ruthless patch cadence on anything internet-facing. These won't stop a determined agentic adversary, but they buy the one thing that's suddenly scarce: time.

The doors attackers are targeting haven't changed. The speed and scale at which they'll be tried just did. JADEPUFFER isn't the exception that proves we're safe — it's the proof of concept that says the pattern is now industrializable.

The question for every board and security leader this quarter is simple: if the attacker never sleeps and never stops, how fast can we?
